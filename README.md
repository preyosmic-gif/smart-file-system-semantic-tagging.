# Smart File System with Semantic Tagging

**Operating Systems Mini Project | B.Tech CSE**

## 1. Project Overview

The Smart File System with Semantic Tagging is a Linux-based application that helps users organize, index, summarize, and search text documents and PDF files.

Traditional file systems primarily organize files using names, folders, and file paths. This project adds a metadata indexing and semantic tagging layer to make documents easier to find based on their content.

The application uses Python, Streamlit, SQLite, Linux extended attributes, PyMuPDF, and the OpenAI API for AI-powered document summaries and tags.

## 2. Problem Statement

As the number of documents on a computer increases, locating a particular file becomes difficult when the user does not remember its exact filename or location.

This project aims to solve that problem by extracting document text, generating summaries, assigning meaningful tags, storing searchable metadata, and providing a simple dashboard to search indexed files.

## 3. Project Objectives

- Automatically scan directories for supported documents.
- Extract text from TXT and PDF files.
- Generate summaries of document content.
- Assign meaningful tags to documents.
- Store file metadata in an SQLite database.
- Save semantic tags as Linux extended attributes where supported.
- Search indexed documents by filename, file path, summary, or tags.
- Provide a user-friendly dashboard using Streamlit.

## 5. System Architecture

The project follows this workflow:

1. The user selects a directory in the dashboard.
2. The scanner finds supported TXT and PDF files.
3. The text extraction module reads their contents.
4. The metadata generator creates summaries and tags using either AI or rule-based logic.
5. The SQLite database stores file information, summaries, and tags.
6. Linux extended attributes store tags on supported filesystems.
7. The search interface retrieves matching indexed records and displays them to the user.

**Architecture flow:**

`User → Streamlit Dashboard → Directory Scanner → Text Extraction → Summary & Tag Generation → SQLite Database + Extended Attributes → Search Results`

## 6. Main Features

### 6.1 Directory Scanning

The application recursively scans the selected directory and identifies supported `.txt` and `.pdf` files.

### 6.2 Text Extraction

Text files are read using Python's file-handling functions. PDF text is extracted using PyMuPDF.

### 6.3 Rule-Based Tagging

The application checks document text and filenames for predefined keywords. Based on these keywords, it assigns tags such as:

- `lecture_notes`
- `operating_systems`
- `database`
- `report`
- `todo_list`
- `cpu_scheduling`
- `programming`

This mode works without an OpenAI API key.

### 6.4 AI-Generated Summaries and Semantic Tags

When AI scanning is selected and the API is configured, the application sends a limited portion of document text to the OpenAI API.

The model returns a short summary and relevant tags in JSON format. If the AI request fails, the application attempts to use rule-based metadata instead.

AI-generated results depend on API availability, model access, network connectivity, and account usage limits.

### 6.5 Metadata Storage

The SQLite database, `file_index.db`, stores the following information:

- File path
- Filename
- File extension
- File size
- Last modified timestamp
- Summary
- Tags

The database is created automatically when the application starts.

### 6.6 Linux Extended Attributes

The application attempts to store tags in the `user.semantic_tags` extended attribute of each indexed file.

This demonstrates an operating-system-level metadata feature. Support depends on the filesystem and its configuration.

### 6.7 Search Interface

Users can search indexed records by filename, path, summary, or tags. Matching files are displayed with their metadata and summaries.

## 8. Installation and Setup

### Prerequisites

- Windows with Ubuntu on WSL2, or a compatible Linux environment
- Python 3
- Internet connectivity for AI features
- An OpenAI API key for AI-generated metadata

### Step 1: Open Ubuntu

From Windows PowerShell, run:

```bash
wsl -d Ubuntu
```

### Step 2: Navigate to the project folder

```bash
cd ~/smart-file-system
```

If you downloaded the project into another directory, navigate to that location instead.

### Step 3: Create a virtual environment

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Step 4: Install dependencies

```bash
python -m pip install streamlit pymupdf openai
```

### Step 5: Configure the OpenAI API key (AI mode only)

Obtain an API key from the OpenAI developer platform. API usage may incur separate charges.

In the same terminal, enter:

```bash
read -s -p "Enter your API key: " OPENAI_API_KEY
echo
export OPENAI_API_KEY
```

Verify that a key is available without displaying its value:

```bash
python -c 'import os; print(bool(os.getenv("OPENAI_API_KEY")))'
```

The expected result is `True`.

Do not place API keys in source code, README files, screenshots, or public repositories. This environment-variable configuration lasts only for the current terminal session.

### Step 6: Launch the application

```bash
streamlit run app.py
```

Open the local address displayed in the terminal, usually:

http://localhost:8501

Keep the terminal running while using the dashboard.

## 9. How to Use the Application

1. Start the Streamlit application.
2. Enter the directory to scan in the sidebar.
3. Select **Rule-based scan** for keyword-based metadata or **AI scan** for AI-generated summaries and tags.
4. Wait for indexing to finish.
5. Review the number of indexed files and scan messages.
6. Expand a file entry to inspect its path, size, summary, and tags.
7. Search using a filename, topic, or tag.
8. Run another scan after adding documents to the selected directory.

For initial testing, use the supplied sample documents.

## 10. Database Design

The application uses an SQLite table named `files`.

| Column | Description |
|---|---|
| `path` | Primary key containing the file path |
| `name` | Filename |
| `extension` | File extension |
| `size` | File size in bytes |
| `modified` | Last modified timestamp |
| `summary` | Stored document summary |
| `tags` | JSON-encoded list of tags |

The file path is the primary key, so indexing the same path again updates its stored record rather than creating a duplicate row.

## 11. Operating System Concepts Demonstrated

- **Directory traversal:** recursively visiting files in a directory tree.
- **File operations:** reading file contents and retrieving file properties.
- **File metadata:** maintaining filename, path, size, modification time, summary, and tags.
- **Extended attributes:** associating semantic tag metadata with files.
- **Persistent storage:** storing indexed metadata in an SQLite database.
- **Search and retrieval:** filtering indexed records using document metadata.
- **Resource and error handling:** handling unreadable files and unavailable AI services.

## 13. Limitations

- The current implementation supports TXT and PDF files only.
- PDF extraction depends on the availability of extractable text; scanned documents may require OCR.
- Rule-based tagging depends on predefined keywords.
- AI scanning requires a working API key, network access, an accessible model, and sufficient API quota.
- Only a limited portion of each document is sent for AI analysis.
- Search is performed over indexed metadata, not by comparing vector embeddings.
- Linux extended attributes may not work on every filesystem or mounted directory.
- The application is a local prototype, not a production-grade file manager.
- The dashboard is not publicly hosted by default.

## 15. Conclusion

The Smart File System with Semantic Tagging demonstrates how operating system file operations and metadata management can be combined with a searchable database and AI-assisted document understanding.

The project provides a simple interface for indexing documents, generating summaries, assigning tags, and retrieving files by their content-related metadata. It also demonstrates Linux extended attributes and persistent storage through SQLite.

The prototype can be extended with more advanced semantic search, OCR, and automated indexing in future work.
